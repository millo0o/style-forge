# STYLE FORGE macOS 승인 적용 프로그램

Node.js 22 이상이 필요합니다. 서버·FTP 비밀번호는 이 배포 파일에 포함되지 않습니다.

1. 압축을 풀고 Node.js를 설치합니다.
2. 협업 서버에 담당자로 로그인 → 공개키 다운로드. 신뢰하는 서버에서 받은 키만 사용합니다.
3. `mkdir -p ~/.style-forge` 후 connector.example.json을 `~/.style-forge/connector.json`으로 복사하고 실제 호스트·계정·스킨 루트·공통 레이아웃·사이트 URL·공개키 경로를 입력합니다. 비밀번호는 넣지 않습니다.
4. 터미널에서 압축 해제 폴더로 이동해 `bash START-MAC.command`를 실행합니다. 서명된 네이티브 Mac 앱이 아니라 Node 기반 터미널 프로그램입니다.
5. 비밀번호를 비공개 입력하고 APPLY를 선택합니다. macOS 파일 선택 창에서 담당자의 승인 JSON을 선택합니다.
6. 프로그램이 대상 스킨을 읽고 전후 코드 review.txt를 만듭니다. 사이트·스킨·공통 레이아웃·생성 CSS를 확인하고 APPLY를 입력해야 쓰기를 수행합니다.
7. 성공 후 백업 폴더의 receipt.json을 검토함에 업로드해 담당자가 적용 상태를 기록합니다. 서버가 FTP 성공을 자동으로 인증한 상태는 아닙니다.
8. 복원은 ROLLBACK으로 백업 폴더를 선택합니다. 적용 이후 파일이 변경되면 해시 충돌로 복원을 중단합니다.

FTPS는 인증서 검증을 유지합니다. 서버가 평문 FTP만 제공하면 protocol을 ftp로 바꾸고 allowPlainFTP: true를 명시적으로 설정해야 합니다. 평문 FTP는 비밀번호와 파일이 암호화되지 않습니다. SFTP는 현재 지원하지 않습니다.

자동 적용은 기존 CSS 선언을 덮어쓰지 않고 승인된 페이지별 override CSS와 loader를 추가하고 지정한 공통 HTML 레이아웃에 연결합니다. 카페24는 @js 지시문, 일반 HTML은 layoutMode: html의 script 태그를 사용합니다. 실제 공통 레이아웃 경로와 publicBase URL은 스킨마다 다르므로 직접 확인해야 합니다. UTF-8, </head>가 있는 레이아웃만 자동 연결합니다. 사이트 CSP와 실제 카페24 모듈 처리는 운영 적용 전에 테스트 스킨에서 확인하세요.

서명 확인·백업·검토 이후 해시 재확인·쓰기·업로드 후 해시 검증·실패 시 복원을 수행합니다. FTP는 다중 파일 트랜잭션을 지원하지 않으므로 실패나 동시 업로드 시 백업을 확인하세요. 준비 단계는 파일·폴더를 읽는 작업이며 새 폴더를 만들지 않아야 합니다. 로컬에서 먼저 검증하려면 protocol: local과 실제 작업 폴더 root를 사용할 수 있습니다.

실제 FTP 적용에는 approvalServer와 reviewEmail 설정도 필요합니다. APPLY 직전에 협업 서버 비밀번호를 비공개로 입력하고 담당자 역할·승인 버전·항목 상태를 재확인합니다. 승인 변경/취소 뒤에는 새 패키지를 받아야 합니다. 인증 정보가 담긴 URL과 사이트 외부 경로는 사용하지 않습니다.
